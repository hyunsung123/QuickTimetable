# QuickTimeTable

Expo SDK 58 + React Native + TypeScript로 구현한 개인용 캘린더입니다. 기존 `src/app` 라우팅과 SDK 버전을 유지합니다. 서버나 로그인 없이 기기의 SQLite에 저장합니다.

## 실행

Windows PowerShell에서 실행합니다. `.ps1` 실행 정책의 영향을 피하려면 `npm.cmd`, `npx.cmd`를 사용하세요.

```powershell
cd C:\Users\janghyunsung\Desktop\QuickTimeTable\mobile
npm.cmd install
npx.cmd expo start --clear
```

iPhone과 PC를 같은 네트워크에 연결하고, Expo Go에서 터미널 QR 코드를 스캔합니다. 이미 8081번 포트에 개발 서버가 있다면 기존 서버를 재시작하거나 `--port 8082`를 지정하세요. 추가한 `expo-sqlite`, `expo-haptics`는 SDK 58 호환 버전이며, 별도의 사용자 정의 네이티브 코드는 없습니다.

## 사용 방법

- **달력**: 일요일부터 시작하는 월간 달력입니다. 날짜를 탭하면 아래의 일정 목록이 바뀝니다. 이전·다음 달, 오늘 이동, 일정 추가·편집·삭제를 지원합니다.
- **주간 계획**: 월요일부터 일요일까지 00:00–24:00을 30분 간격으로 표시합니다. 처음에는 08:00 위치로 스크롤합니다.
- **일정 생성**: 빈 칸을 탭하고 제목을 입력하여 저장합니다. 선택한 칸부터 30분 길이로 시작합니다.
- **시간 조절**: 블록 위·아래의 흰 손잡이를 드래그합니다. 위쪽은 시작 시간, 아래쪽은 종료 시간을 조절합니다. 최소 길이는 30분입니다.
- **일정 이동**: 블록의 가운데를 약 0.3초 누른 뒤 드래그합니다. 일정 길이를 유지하면서 시간과 요일이 바뀝니다. 손을 놓으면 저장됩니다. 짧게 탭하면 편집 창이 열립니다.
- **확대 편집**: 요일을 선택하거나 `확대 편집`을 누르면 열 너비가 넓어집니다. 좌우로 스크롤해 다른 요일을 볼 수 있고 날짜 헤더와 시간 눈금은 각각 맞춰 표시됩니다.
- **기본 시간표**: 설정 → 기본 시간표 관리에서 같은 방식으로 생성·이동·크기 조절·편집·삭제합니다.

드래그는 30분 단위로 맞춰지며, 변경 중인 요일·시간이 화면 아래에 표시됩니다. 기기가 지원하면 단계가 바뀔 때 가벼운 햅틱이 발생합니다. 스크롤은 블록 중앙을 짧게 밀거나 빈 영역에서 시작하세요.

## 저장과 기본 시간표 적용 규칙

`templates`는 요일 기반 원본, `events`는 실제 날짜별 일정, `initialized_weeks`는 적용을 마친 주의 월요일을 저장합니다. 주간 화면을 **처음 여는 시점**에 현재 기본 시간표를 복사합니다. 월간 화면을 보기만 해서는 기본 일정을 미리 생성하지 않습니다.

이미 연 주는 기본 시간표를 변경해도 덮어쓰지 않습니다. 기본 시간표가 비어 있을 때 연 주도 적용 완료로 기록됩니다. 따라서 그 뒤 기본 시간표를 만들어도 해당 주에는 소급 적용되지 않으며, 아직 열지 않은 주부터 적용됩니다. 날짜별 일정의 수정·삭제는 원본과 다른 주에 영향을 주지 않습니다. 삭제한 기본 일정도 해당 주에 다시 나타나지 않습니다.

적용과 주 기록은 하나의 트랜잭션에서 처리하고, 저장 작업은 순차 실행합니다. 실패하면 부분 복사를 롤백합니다. 저장 실패 시 기존 데이터가 유지되고 한국어 오류 안내가 표시됩니다. 로딩 실패 시 빈 달력을 편집하도록 허용하지 않습니다.

일정에는 ID, 캘린더 ID, 제목, 로컬 날짜, 시작·종료 분, 색상, 생성·수정 시각과 기본 시간표 원본 ID가 있습니다. 날짜는 로컬 `YYYY-MM-DD`, 시간은 해당 날짜의 0–1440분입니다. `24:00`은 같은 날짜의 종료 경계입니다. 자정을 넘는 일정은 날짜별로 나누어 입력합니다. 생성·수정 시각만 UTC ISO 형식입니다.

기기의 앱 데이터 삭제·앱 제거 시 로컬 일정도 삭제될 수 있습니다. 현재 버전에는 클라우드 동기화와 백업 기능이 없습니다.

## 파일 구성

| 위치 | 역할 |
|---|---|
| `src/app/_layout.tsx` | 공통 저장소, Safe Area, 제스처 루트, Stack |
| `src/app/(tabs)/` | 달력·주간 계획 두 개의 하단 탭 |
| `src/app/settings.tsx`, `default-timetable.tsx` | 설정 및 기본 시간표 경로 |
| `src/components/calendar/` | 월간 달력 |
| `src/components/events/` | 일정 입력·수정·삭제 모달 |
| `src/components/timetable/` | 공통 주간 화면, 시간 격자, 블록 제스처 |
| `src/hooks/use-calendar.tsx` | 모든 화면이 공유하는 일정 상태 |
| `src/lib/repository.ts`, `database.ts` | SQLite 스키마, 저장, 주별 초기화 |
| `src/lib/dates.ts`, `timetable.ts` | 로컬 날짜 계산, 스냅·이동·겹침 계산 |
| `tests/calendar.test.cjs` | 실제 SQLite 기반 저장·적용 및 경계 테스트 |

기존 예제 홈·Explore와 사용하지 않는 예제 탭 파일은 실제 화면으로 대체했습니다. `app.json`은 표시 이름, 밝은 테마, SQLite 플러그인과 웹 SQLite 헤더를 설정합니다. Metro는 SQLite 웹 워커의 WASM 파일과 개발용 격리 헤더를 지원합니다. SDK 버전 및 iOS·Android 네이티브 디렉터리는 변경하지 않았습니다.

## 자동 검증

테스트에는 Node.js 24 이상이 필요합니다. Node 내장 SQLite로 실제 SQL을 실행하며 테스트 데이터는 임시 파일 또는 메모리에만 생성합니다.

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npx.cmd expo install --check
npx.cmd --yes expo-doctor
npx.cmd expo export --platform ios --platform android --platform web
```

자동 테스트 범위: 날짜·월·연도·윤년·DST 경계, 24:00 처리, 위·아래 조절, 요일 이동, 30분 스냅, 최소 길이, 겹치는 일정 배치, 일정 CRUD 및 정렬, 주별 기본 일정 생성, 동시 진입 중복 방지, 삭제 후 재진입, 원본·주간 사본 독립성, 이미 연 미래 주 보존, 부분 실패 롤백, 실제 DB 파일을 닫고 다시 열었을 때 복원.

번들 생성은 컴파일 검증이며, 실기기에서의 터치·레이아웃 검증을 대신하지 않습니다.

2026-11-10 검증 결과: TypeScript·ESLint 통과, 자동 테스트 16/16 통과, SDK 의존성 호환성 통과, Expo Doctor 20/20 통과, iOS·Android Hermes 및 웹 번들 생성 성공. 설치된 Expo Router의 실제 경로 해석기로 두 하단 탭의 목적지도 확인했습니다. 로컬 웹 서버의 HTTP 200 응답은 확인했으나, 연결된 브라우저 및 iPhone이 없어 화면 조작을 검증하지는 않았습니다.

## iPhone Expo Go 수동 확인

아래 항목은 실기기 검증이 필요합니다.

1. 처음 열면 월간 달력이 나타나고 노치·하단 홈 표시기와 버튼이 겹치지 않는지 확인합니다. 날짜·이전 달·다음 달·오늘을 눌러 확인합니다.
2. 주간 계획 → 빈 09:00 칸 → 제목을 입력해 저장합니다. 09:00–09:30 블록이 생성되는지 확인합니다.
3. `확대 편집`에서 블록 아래 손잡이를 한 칸 내려 종료가 10:00으로 바뀌는지 확인합니다. 위 손잡이를 움직여 종료는 유지하고 시작만 바뀌는지, 30분보다 작아지지 않는지 확인합니다.
4. 블록 중앙을 길게 눌러 다른 시간과 요일로 이동합니다. 길이가 유지되고 하단 시간 표시가 바뀌는지, 손을 놓은 뒤 월간·일간 목록에 반영되는지 확인합니다.
5. 빈 영역과 블록 중앙에서 짧게 밀어 스크롤하고, 드래그와 충돌하지 않는지 확인합니다. 확대 보기의 가로 스크롤, 헤더·눈금 정렬, 겹친 블록의 편집도 확인합니다.
6. 일정을 탭해 제목·날짜·시간·색상을 수정합니다. 키보드가 저장 버튼을 가리지 않는지 확인한 뒤 삭제도 시험합니다.
7. 설정에서 기본 시간표를 만든 다음 **아직 열지 않은 주**로 이동합니다. 기본 일정이 한 번 생성되는지 확인합니다. 해당 주에서 변경·삭제한 뒤 다른 주에 갔다 돌아와 보존 여부를 확인합니다.
8. 기본 시간표 원본을 변경한 뒤 이미 연 주는 유지되고 새 주에만 변경분이 적용되는지 확인합니다.
9. 23:30–24:00 일정, 일요일→월요일, 12월→1월 경계를 확인합니다.
10. 앱을 완전히 종료하고 다시 열어 일정·기본 시간표·삭제 상태가 유지되는지 확인합니다. 햅틱과 작은 화면에서의 손잡이 조작감도 확인합니다.

Android의 뒤로 가기·키보드·드래그 동작도 실기기에서 별도로 확인하세요.
