# QuickTimeTable

Expo SDK 58 + React Native + TypeScript로 구현한 개인용 캘린더입니다. 기존 `src/app` 라우팅과 SDK 버전을 유지합니다. 서버나 로그인 없이 기기의 SQLite에 저장합니다.

## 실행

Windows PowerShell에서 실행합니다. `.ps1` 실행 정책의 영향을 피하려면 `npm.cmd`, `npx.cmd`를 사용하세요.

```powershell
cd C:\Users\janghyunsung\Desktop\QuickTimeTable\mobile
npm.cmd install
npx.cmd expo start --clear
```

iPhone과 PC를 같은 네트워크에 연결하고, Expo Go에서 터미널 QR 코드를 스캔합니다. 이미 8081번 포트에 개발 서버가 있다면 기존 서버를 재시작하거나 `--port 8082`를 지정하세요. 추가한 `expo-sqlite`, `expo-haptics`는 SDK 58 호환 버전이며, 별도의 사용자 정의 네이티브 코드는 없습니다.

## 사용 방법

- **달력**: 일요일부터 시작하는 월간 달력입니다. 날짜별 일정 색상을 시작 시간순으로 가로 4개, 최대 2줄(8개) 표시합니다. 날짜를 탭하면 아래의 일정 목록이 바뀝니다. 이전·다음 달, 오늘 이동, 일정 추가·편집·삭제를 지원합니다.
- **주간 계획**: 월요일부터 일요일까지 00:00–24:00을 30분 간격으로 표시합니다. 한 행은 26px이고 처음에는 08:00 위치로 스크롤합니다. 모든 블록은 요일 열 전체 너비를 사용합니다.
- **일정 생성**: 빈 칸을 탭하고 제목을 입력하여 저장합니다. 선택한 칸부터 30분 길이로 시작합니다.
- **시간 조절**: 블록 오른쪽 위·아래의 작은 흰 손잡이를 드래그합니다. 맞닿은 두 블록 사이에서는 공유 경계선이 움직입니다. 한쪽이 늘면 다른 쪽이 줄고, 두 블록의 반대쪽 끝은 고정됩니다. 최소 길이는 각각 30분입니다. 작은 블록은 확대 편집으로 조절할 수 있습니다.
- **일정 이동**: 블록을 누르면 살짝 줄어들고, 약 350ms 후 선택 표시와 햅틱이 발생합니다. 중앙을 누른 채 드래그하면 살짝 뜨면서 손가락을 따라 움직입니다. 저장 시간은 30분 단위이며, 놓거나 취소·화면 이탈하면 눌림 상태가 복원됩니다. 짧게 탭하면 편집 창이 열립니다.
- **복사·붙여넣기·삭제**: 블록을 길게 누르고 움직이지 않은 채 놓으면 컴팩트한 `복사 | 삭제` 말풍선이 나타납니다. 삭제는 확인 후 해당 블록만 제거합니다. 복사 후 빈 시간대를 길게 눌렀다 놓으면 `붙여넣기`가 나타납니다. 화면을 옮겨도 복사한 제목·색상·길이를 유지하며 여러 번 붙여넣을 수 있습니다. 다른 곳을 누르면 메뉴가 닫힙니다. 실제 드래그 후에는 메뉴를 열지 않습니다.
- **확대 편집**: 요일을 선택하거나 `확대 편집`을 누르면 열 너비가 넓어집니다. 좌우로 스크롤해 다른 요일을 볼 수 있고 날짜 헤더와 시간 눈금은 각각 맞춰 표시됩니다.
- **다중 시간표**: 설정 → 기본 시간표 관리에서 저장된 시간표 목록을 봅니다. 왼쪽 체크로 기본 시간표 하나를 선택하고, 이름을 누르면 해당 시간표만 편집합니다. `+ 시간표 추가`에서 빈 시간표를 만들거나 이전 시간표를 불러올 수 있습니다. 이름 변경·기본 지정·삭제와 모든 블록 편집을 자동 저장합니다.
- **주간 시간표 불러오기**: 주간 날짜 이동 아래의 버튼을 눌러 저장된 템플릿을 선택하고 미리본 뒤 `불러오기`를 누릅니다. 기본으로 체크한 시간표가 목록 맨 위에 표시됩니다. 현재 보고 있는 주에만 새 ID로 복사하며, 기존 일정이 있으면 교체 확인을 받습니다. 취소하면 원본을 유지합니다.
- **주간 전체 삭제**: 주간 화면의 `전체 삭제`에서 확인하면 현재 선택한 월~일 일정만 삭제합니다. 다른 주·템플릿·기본 선택·클립보드는 유지합니다. 비어 있는 주에서는 비활성화됩니다.
- **템플릿 만들기·교체**: 기본 시간표 관리에서 이전 주간계획 또는 저장된 다른 시간표를 불러와 새 템플릿을 만들거나 현재 템플릿을 교체할 수 있습니다. 원본과 실제 주간 일정은 변경하지 않습니다.
- **캘린더 공유**: 세 번째 하단 탭입니다. 현재는 ‘개발 중’ 안내만 표시합니다.
- **마이페이지**: 네 번째 하단 탭입니다. 현재는 ‘개발 중’ 안내만 표시합니다.
- **테스트 데이터 초기화**: 설정 하단의 테스트 섹션에서 확인 후 모든 일정·시간표·기본 선택·주 기록·클립보드를 비웁니다. 취소하거나 DB 저장에 실패하면 원본을 유지합니다.

드래그는 30분 단위로 맞춰지며, 변경 중인 요일·시간이 화면 아래에 표시됩니다. 기기가 지원하면 단계가 바뀔 때 가벼운 햅틱이 발생합니다. 스크롤은 블록 중앙을 짧게 밀거나 빈 영역에서 시작하세요.

빈 공간에서는 블록 하나만 늘리거나 줄입니다. 이웃 블록에 닿는 순간부터 같은 드래그 안에서 경계선을 공유하며, 방향을 되돌려도 두 블록 사이를 벌리지 않습니다. 다른 블록을 통째로 이동하거나 연쇄적으로 밀지 않습니다. 기존에 겹쳐 있어 경계선이 모호한 경우에는 조절을 제한합니다.

이동·붙여넣기는 시작 위치가 다른 일정 안이면 거부합니다. 시작 위치가 비어 있으면 다음 블록 시작 또는 24:00까지의 빈 공간에 맞춰 길이를 줄입니다. 공간이 충분하면 원래 길이를 유지하며, 최소 길이는 30분입니다. 이동 중 축소된 높이를 미리 보여주고, 배치 불가는 붉은 반투명 표시로 알립니다. 실패·취소 시 원래 위치와 크기로 돌아갑니다. 일정 입력·편집 창에서 직접 지정한 시간은 자동 축소하지 않고 겹침 오류를 표시합니다.

붙여넣기는 새 ID를 생성하며 원본을 유지합니다. 축소해서 붙여넣어도 클립보드의 원래 길이는 바뀌지 않습니다. 앱 내부 클립보드는 화면 간 공유되며 앱을 완전히 종료하면 초기화됩니다. 이 기능은 기본 시간표에서도 동일하게 사용할 수 있습니다.

기존 DB에 겹친 일정이 있다면 자동으로 삭제하거나 바꾸지 않습니다. 시간표 위의 안내 목록에서 가려진 일정도 선택해 시간을 수정할 수 있습니다. 기존 시간을 그대로 둔 제목·색상 편집은 허용하고, 새 시간은 충돌 없이 지정해야 합니다. 겹친 원본의 시간표 불러오기는 전체 취소하고 수정 안내를 표시합니다. [겹침 방지·자동 맞춤 상세](docs/PLACEMENT_AND_DENSITY.md)에 정책과 변경 파일을 정리했습니다.

## 저장과 기본 시간표 적용 규칙

`timetable_presets`는 시간표 이름·기본 선택, `templates`는 `presetId`에 속하는 요일 기반 블록, `events`는 실제 날짜별 일정, `initialized_weeks`는 방문·작성한 주의 월요일을 저장합니다. **자동 적용은 없습니다.** 앱 실행, 주 이동, 기본 지정과 템플릿 편집은 실제 일정을 생성하지 않습니다. 과거·현재·미래 모두 처음 여는 주는 비어 있으며, 이미 저장된 일정은 보존합니다.

기본 체크는 불러오기 목록에서 우선 표시할 시간표를 선택합니다. 나머지는 저장 순서대로 표시하며, 불러올 시간표를 선택해도 체크가 바뀌지 않습니다. 사용자가 주간 화면에서 직접 불러오기할 때만 요일을 선택한 주의 실제 날짜로 복사합니다. 원본과 사본은 독립적이며, 삭제한 일정도 자동으로 다시 나타나지 않습니다.

수동 교체는 템플릿 존재·내부 겹침 검증 → 교체 동의 확인 → 선택한 주 삭제 → 새 ID로 복사 → 주 기록 순서로 하나의 트랜잭션에서 처리합니다. 미리보기 이후 다른 일정이 생겨도 교체 동의 없이는 삭제하지 않습니다. 주간 전체 삭제도 하나의 트랜잭션이며, 실패하면 모든 변경을 롤백합니다. 성공한 스냅샷만 화면에 반영합니다.

공유 경계선으로 변경한 두 일정도 하나의 SQLite 트랜잭션으로 저장합니다. 두 번째 쓰기나 스냅샷 읽기에 실패해도 전체 롤백하며, 성공한 스냅샷만 Provider에 반영합니다. 드래그 시작 당시의 시간이 바뀌었거나 일정이 삭제된 경우에는 오래된 변경을 적용하지 않습니다. 일정 생성·편집과 붙여넣기의 충돌 확인 및 저장, 시간표 생성·교체·삭제·기본 선택도 트랜잭션으로 처리합니다. 충돌 범위는 실제 일정의 같은 날짜, 템플릿의 같은 presetId·요일이며, 정확히 맞닿는 시간은 허용합니다.

현재 SQLite `user_version`은 3입니다. 기존 v3의 `applyFromWeek` 값과 열은 보존하지만 일정 생성에 사용하지 않습니다. v1/v2 이전 경로도 유지하며 새 열에는 적용일을 배정하지 않습니다. DB 삭제나 파괴적 마이그레이션은 없습니다. [수동 불러오기 상세](docs/MANUAL_WEEK_IMPORT.md)에 변경 파일과 검증 범위를 정리했습니다.

전체 초기화는 이 앱 DB의 데이터 행만 하나의 트랜잭션에서 삭제하며 테이블·인덱스·버전과 내부 캘린더는 유지합니다. 성공 후 Provider 데이터와 클립보드를 비우고 오늘의 빈 달력으로 돌아갑니다. 실패 시 삭제 전체를 롤백합니다. 초기화 후 재시작해도 시간표를 자동으로 다시 만들지 않습니다. 다음에 주간 화면을 열면서 새로 남기는 빈 주 기록은 정상적인 초기화 기록입니다.

일정에는 ID, 캘린더 ID, 제목, 로컬 날짜, 시작·종료 분, 색상, 생성·수정 시각과 기본 시간표 원본 ID가 있습니다. 날짜는 로컬 `YYYY-MM-DD`, 시간은 해당 날짜의 0–1440분입니다. `24:00`은 같은 날짜의 종료 경계입니다. 자정을 넘는 일정은 날짜별로 나누어 입력합니다. 생성·수정 시각만 UTC ISO 형식입니다.

기기의 앱 데이터 삭제·앱 제거 시 로컬 일정도 삭제될 수 있습니다. 현재 버전에는 클라우드 동기화와 백업 기능이 없습니다.

## 자동 검증

테스트에는 Node.js 24 이상이 필요합니다. Node 내장 SQLite로 실제 SQL을 실행하며 테스트 데이터는 임시 파일 또는 메모리에만 생성합니다.

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npx.cmd expo install --check
npx.cmd --yes expo-doctor
npx.cmd expo export --platform ios --platform android --platform web
```

자동 테스트 범위: 날짜·월·연도·윤년·DST 경계, 24:00 처리, 위·아래 조절, 요일 이동, 30분 스냅, 최소 길이, 겹침 거부와 빈 공간 자동 맞춤, 일정 CRUD 및 정렬, 자동 적용 제거, 선택한 주에만 수동 불러오기·전체 삭제, 교체 취소와 동시 요청 보호, 기본 체크 우선 표시, 사본 독립성, 부분 실패 롤백, 실제 DB 재실행 후 삭제 상태 유지, 4×2 일정 점, 네 탭 구성.

추가 테스트 범위: 공유 경계선 위·아래 조절과 양쪽 손잡이의 동일성, 빈 공간을 지나 접촉한 뒤 반대 방향으로 이동, 세 번째 블록과 다른 요일 보존, 겹침 제한, 두 블록 동시 미리보기·취소·저장 실패 복원, 일반 일정·기본 시간표 트랜잭션의 두 번째 쓰기 실패 롤백, 반복 붙여넣기·새 ID·충돌 취소, 350ms 정지 후 복사와 실제 이동의 구분, 스크롤 취소 후 메뉴 억제, 말풍선 바깥 터치 닫기, 화면 변경 후 클립보드 유지, Provider의 원자적 상태 반영.

UI 테스트는 실제 React 컴포넌트와 훅을 실행하며, 네이티브 뷰 및 제스처 이벤트 전달부는 테스트 대역을 사용합니다. `react-test-renderer`는 React와 같은 19.3.0 버전의 개발 의존성으로만 추가했습니다. 네이티브 제스처 인식, 실제 화면 배치 및 햅틱은 [실기기 확인 절차](docs/TOUCH_TESTS.md)를 따릅니다.

번들 생성은 컴파일 검증이며, 실기기에서의 터치·레이아웃 검증을 대신하지 않습니다.

2026-11-13 검증 결과: TypeScript·ESLint·Expo 의존성 검사 통과, 자동 테스트 137/137 통과. iPhone의 실제 터치 조작은 아직 검증하지 않았습니다. 이번 작업에서 Expo 호환성 검사에 따라 SDK 58 내 권장 패치 버전을 맞췄습니다.

## iPhone Expo Go 수동 확인

아래 항목은 실기기 검증이 필요합니다.

1. 처음 열면 월간 달력이 나타나고 노치·하단 홈 표시기와 버튼이 겹치지 않는지 확인합니다. 날짜·이전 달·다음 달·오늘을 눌러 확인합니다.
2. 주간 계획 → 빈 09:00 칸 → 제목을 입력해 저장합니다. 09:00–09:30 블록이 생성되는지 확인합니다.
3. `확대 편집`에서 블록 아래 손잡이를 한 칸 내려 종료가 10:00으로 바뀌는지 확인합니다. 위 손잡이를 움직여 종료는 유지하고 시작만 바뀌는지, 30분보다 작아지지 않는지 확인합니다.
4. 블록 중앙을 길게 눌러 다른 시간과 요일로 이동합니다. 빈 공간이 충분하면 길이를 유지하고, 부족하면 맞춰 줄어드는지 확인합니다. 점유된 시작 위치는 거부하고 원래 크기로 복귀해야 합니다. 손을 놓은 뒤 월간·일간 목록에도 반영되어야 합니다.
5. 빈 영역과 블록 중앙에서 짧게 밀어 스크롤하고, 드래그와 충돌하지 않는지 확인합니다. 확대 보기의 가로 스크롤, 헤더·눈금 정렬, 겹친 블록의 편집도 확인합니다.
6. 일정을 탭해 제목·날짜·시간·색상을 수정합니다. 키보드가 저장 버튼을 가리지 않는지 확인한 뒤 삭제도 시험합니다.
7. 기본 시간표를 만들고 체크한 뒤 과거·현재·미래의 빈 주를 엽니다. 모두 빈 상태여야 합니다. 주간의 `시간표 불러오기`에서 체크된 시간표가 맨 위인지 확인하고, 다른 시간표를 미리본 뒤 적용합니다. 기존 일정이 있는 주에서는 교체 확인의 취소·확인을 각각 시험합니다.
8. 주간 `전체 삭제`를 취소하면 유지되고, 확인하면 선택한 주만 비워지는지 확인합니다. 다른 주·템플릿·클립보드는 유지되어야 하며 재시작 후에도 빈 상태여야 합니다. 다른 템플릿을 다시 불러올 수 있어야 합니다.
9. 23:30–24:00 일정, 일요일→월요일, 12월→1월 경계를 확인합니다.
10. 앱을 완전히 종료하고 다시 열어 일정·기본 시간표·삭제 상태가 유지되는지 확인합니다. 햅틱과 작은 화면에서의 손잡이 조작감도 확인합니다.
11. 한 날짜에 9개 이상 일정을 만들어 점이 시간순 색상으로 4개씩 최대 2줄인지 확인합니다. 네 하단 탭의 선택 표시, 마이페이지 문구와 홈 표시기 여백도 확인합니다.

Android의 뒤로 가기·키보드·드래그 동작도 실기기에서 별도로 확인하세요.

복사·붙여넣기와 공유 경계선의 자세한 검증은 [추가 기능 실기기 체크리스트](docs/TOUCH_TESTS.md)에 정리했습니다.
